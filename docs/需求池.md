## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| 已完成 | 已存在实现与验证证据，且仅针对列明范围 |
| 待开发 | 范围已确认，但尚无完整实现 |
| 待细化 | 范围已确认，包含会影响实现或验收的未定规则 |
| 后续候选 | 未纳入第一版，不自动排期 |

P0 为核心业务闭环；P1 为完整第一版的反馈、通知与交付条件，仍须在正式验收前完成。

## 3. 决策登记（已确认/暂缓）

完整生效规则见 [需求确认单](./需求确认单.md)。D01—D11 的规则已确认，设备及部署具体参数在交付前落实。

| 编号 | 决策内容 | 影响 | 确认结果 |
| --- | --- | --- | --- |
| D01 | 首次账户如何创建，角色如何确定，忘记密码如何处理 | 防止自行冒充审批人，明确 T01 入口 | 已确认：受控创建两人账户、固定角色、管理员重置密码、会话 7 天 |
| D02 | 绑定后是否可换人、解绑，历史账目对双方如何可见 | 影响关系权限、共享提示及历史查询 | 已确认：24 小时一次性邀请码，明确共享范围，第一版不换绑/解绑 |
| D03 | 首次预算生效日期、调整何时生效、跨月预算如何产生 | 影响历史日额度、累计结余与月度归属 | 已确认：首次当日、日额度变更次日、月预算立即生效留版本；下月沿用，不结转 |
| D04 | 哪些固定支出分类不计日额度，谁可修改分类口径 | 影响超支计算及是否可绕过审批 | 已确认：默认生活缴费不计日额度，其余计入；审批人调整次日生效，保留历史 |
| D05 | 退款归属日期、跨月退款、部分/多次退款和超额退款规则 | 影响历史统计及退款约束 | 已确认：关联原支出，可部分/多次且不超原额，跨月退款冲回原消费日 |
| D06 | 已批准未消费申请是否占额度，是否防止多笔承诺超过预算 | 影响申请时的可用额度和审批展示 | 已确认：待审不占用，批准后占完整预计金额，实际支出与承诺分开 |
| D07 | 申请有效期、消费日期变更与跨日处理 | 影响申请是否仍可消费，是否重新审批 | 已确认：仅当天消费有效；跨日重新申请，允许真实当日消费的事后补记 |
| D08 | 已消费关联账目的修改、删除、退款怎样保持审批记录一致 | 防止改单后绕过批准金额或产生悬空申请 | 已确认：更正留轨迹，超批准差额补批不重复记账，有退款记录不删除 |
| D09 | “接近预算”阈值、通知偏好、重复提醒规则和推送接入 | 影响提醒验收和后台到达方式 | 已确认：实际支出 80%/100% 阈值各一次，跨双阈值只提醒高档，推送可关闭 |
