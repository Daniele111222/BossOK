## 需求到交付

```text
已确认产品范围 → 需求池 R 编号 → 功能规格
                                   ↓
                           开发任务 T 编号
                                   ↓
                           验收场景 A 编号
```

已有工程基础使用 R00 记录；业务需求不能因目录、页面入口或用户表存在而标记完成。任务通过全部验收并记录证据后，才更新需求池状态。

产品规则以核心产品需求和明确确认的决策为准；架构规则以架构设计为准。其他文档发现冲突时先核对，不静默采用旧规则。当前结余按已录入账目自动统计，无每日记账确认步骤。

## 维护约定

- `R` 表示需求，`D` 表示决策记录，`T` 表示开发切片，`A` 表示验收场景；编号建立后不复用。
- 修改已确认规则时，先在需求池记录决定及日期，再同步核心产品需求、规格、相关任务和验收场景。
- 任务拆分与验证方案已确认；这不等于已实现、已排期或已创建外部 Issue。当前仅维护本地文档。
- 本地 Git 已初始化，默认分支为 `main`；首次提交前文件处于未跟踪状态，后续使用 Git 跟踪文档与代码变更。
- 不虚构负责人、工期、费用、测试通过记录或真机适配结果。
